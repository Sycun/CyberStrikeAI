# 深度测评

独立于「任务管理」的长程目标工作台，使用 Pi 1.5.2 执行规划、步骤和验收。现有批量队列、Cron、页面和 `/api/batch-tasks` 保持原有行为。

## 使用

在侧边栏进入「深度测评」，填写目标、范围、验收条件，可选模型渠道、角色和项目。保存只创建草稿；点击「开始 / 继续」才执行。

默认任务窗口为 48 小时、Token 预算 2,000,000、512 轮规划、2 个并行步骤。窗口从首次执行计算，包含暂停及服务停机；重新开始不会重置截止时间。暂停后可以明确延长剩余窗口、规划轮数和 Token 预算。

- **概览**：原始目标、范围、当前路线、结论、缺口与截止时间。
- **探索计划**：步骤、前置依赖、结果、分段次数和执行会话。
- **证据回执**：工具参数、成功/失败/结果不明状态及可引用的执行 ID。
- **运行记录**：持久生命周期事件；API 支持按事件游标读取历史。
- **上下文与用量**：Pi 会话累计 Token、当前上下文/窗口、压缩次数、当前可见工具数及工具定义 JSON 大小（字节，不冒充 Token）。

运行中补充方向先保存到数据库，再经 Pi 原生 `steer()` 投递给活跃执行步骤；后续规划及恢复也读取已保存方向。待答复状态可填写信息后继续。协作者须先暂停并以自己的执行身份继续，不能借用其他执行者的身份插话。

## Pi 原生能力与状态归属

Pi 的 `SessionManager` 是会话上下文的唯一权威来源。每个步骤绑定稳定的执行会话；轮数用尽时结束本段，再打开同一 Pi 会话续跑。默认单段软时间上限为 15 分钟，在工具返回后的轮边界判断；单次工具仍受现有工具超时限制，总截止时间是硬边界。

规划器和验收器也使用完整 Pi 会话与显式结构化提交工具。原生重试、模型路由、上下文压缩、工具搜索继续由 SDK 负责。`agent_before_settle` 在未提交结果时最多提醒两次；业务调度使用 SDK `finishTurn` 的结束决策控制分段。扩展的 `continue:false` 不会阻止自然工具循环，不能代替这个预算边界。

深度测评使用 Pi 原生 Skills 解析和渐进披露，仅加载配置的技能目录；读取技能仍通过宿主的 `read_file` 工具和权限检查。工具桥支持参数/输出 schema、结构化结果、annotations、namespace、暴露方式、描述指引及执行模式。平台权限与实际执行继续由 Go 宿主负责，annotations 不赋予权限。

原生压缩保留完整会话；当前任务态势以自定义消息追加，固定的目标、范围和步骤职责放在每段执行指令中。业务上下文有大小上限，优先保留活跃/受阻方向和最近观察。`assessment_memory` 可分页查询被省略的步骤及原始过程；`assessment_trace` 按字符偏移回查完整过程。模型摘要和检查点是观察，不是独立证据。

`assessment_checkpoint` 同时保存业务进度并追加 Pi 原生自定义条目。`assessment_result` 支持 completed、blocked 和 continue；完成必须引用本测评实际成功调用的回执。独立验收使用另一个 Pi 会话，结合原始目标、步骤证据和可检索记录判断缺口。验收仍是模型判断，不能替代人工复测。

## 恢复与边界

SQLite 保存任务、步骤、预算、会话引用、事件和调用回执；Pi JSONL 保存模型上下文，两者以会话/步骤身份关联。

1. 工具派发前先提交调用意图；结果返回后先提交回执，再交还 Pi。回执关联 Pi 原生助手消息条目和 tool-call ID；若回执已提交而 Pi 结果尚未写入就退出，恢复时用该精确身份补回已确认结果，避免把已成功操作重放。
2. 服务恢复时，已完成步骤保留。没有未确认调用的中断步骤可以自动恢复同一会话。已有 Pi 会话文件缺失时会明确受阻，先恢复原文件，避免静默建立空会话重做。
3. 工具意图已提交但结果未提交、或取消时外部效果不明，标记为「待核对」。操作人检查回执及实际执行状态后，才能明确恢复；系统不声称跨外部系统的恰好一次执行。
4. 临时模型故障先由 Pi 退避重试；仍失败则保存任务，30–150 秒后重新调度，连续失败达到上限后受阻。认证、权限和配置错误不作为临时故障循环重试。
5. 连续分段没有新增成功工具证据时停止该步骤；每步骤最多 512 段，任务最多 2,048 个步骤、4,096 轮规划、4 并行；单服务同时最多 8 个活跃测评。
6. 暂停/停止等待本地执行资源收尾。清理未确认时不能直接恢复；用户停止和预算耗尽都不算任务完成。

Token 来自 Pi 全会话用量快照，包含压缩，按会话增量结算防止重复计数。预算停止后续调度；在途请求、供应商缺失 usage 等情况使它不等于供应商账单硬上限。默认 48 小时是允许执行的窗口，不保证固定预算下持续调用模型 48 小时。

当前面向单服务进程，不能让多个实例同时调度同一数据库。范围文字会传给规划和执行；它不是任意 Shell/MCP 工具的网络隔离沙箱。实际限制继承所选角色、实时平台权限、HITL、工具调用拦截及工具自身约束。

新表为 `deep_assessments`、`deep_assessment_events`、`deep_assessment_calls`。不读取或恢复已撤回旧模块的 `assessments`/`long_tasks` 历史任务。删除测评会删除其业务事件/回执，关联执行会话与 Pi 历史按原有会话/运行目录保留策略处理。

## API

所有接口均需登录，使用独立的 `assessments:read/write/delete` 权限与 `deep_assessment` 资源范围；启动及执行另校验 `agent:execute` 和会话权限。

| 接口 | 用途 |
| --- | --- |
| `GET /api/deep-assessments/options` | 可用项目、角色与模型渠道，不返回密钥 |
| `GET / POST /api/deep-assessments` | 分页查询 / 创建草稿 |
| `GET / DELETE /api/deep-assessments/:id` | 详情 / 删除非活动测评 |
| `POST /api/deep-assessments/:id/control/:action` | start、pause、cancel、guidance、answer、retry、budget |
| `GET /api/deep-assessments/:id/events?after=0` | 增量事件 |
| `GET /api/deep-assessments/:id/receipts?offset=0` | 分页工具回执 |
| `GET /api/deep-assessments/:id/report` | 阶段报告，含未完成状态 |

控制请求携带 `revision`；预算和重试检查版本，暂停/停止允许针对较旧快照发出停止指令。结果不明的步骤重试另需 `reconciled:true`，清理未确认另需 `cleanup_confirmed:true`。新预算的 `remaining_seconds` 从当前时间计算，`token_budget` 是累计上限，已消耗用量不清零。

## 验证

隔离回归覆盖依赖推进、分段续跑、持久恢复、结果不明的调用、48 小时截止时间不重置、重复用量快照、跨任务证据隔离和 HTTP 权限。真实 Pi SDK 连接本地模拟模型，覆盖规划—多段执行—真实本地回声工具回执—独立验收；另外验证原生结束钩子、技能渐进披露与结构化检查点。

浏览器使用隔离 API 夹具检查创建不执行、分页、控制、报告、XSS 转义、刷新保留输入、桌面和手机布局；原批量任务浏览器回归一并运行。

这些验证不代表真实供应商模型在真实目标上已连续运行 48 小时。发现质量、长时成本和故障恢复收益需要在相同模型、目标环境、工具和预算下继续对照测量。
