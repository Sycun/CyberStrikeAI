# 深度测评：持续探索与图记忆

独立于「任务管理」的目标工作台，使用 Pi 执行规划、步骤和验收。侧边栏入口位于「对话」下一行；主页面是列表，详情和新建使用右侧抽屉。关闭抽屉不停止后台任务。

## 持续执行

新建只填写名称、目标、范围、验收条件，可选模型、角色、项目、并行步骤和重启恢复。保存为草稿，点击「开始 / 继续」才执行。

**任务没有时间窗口、累计 Token、规划轮数、总步骤数或累计执行分段次数上限。** Token 和轮次保留为观测统计，不触发任务结束。任务围绕验收条件推进，直到完成、用户暂停/停止，或需要用户补充信息、核对结果不明的操作。

一个方向停滞时交还规划器换路；暂时没有新方向或验收仍有缺口时保留状态，进入「等待新进展」并定时重评。临时模型故障退避后继续，没有累计重试次数终止条件；认证、权限等需修复的问题会明确显示。等待期间不保持一个空转的模型请求。

单次工具超时、模型上下文容量、每次规划增量和并行工作数仍按执行环境处理。Pi 在轮边界保存一个执行分段，再恢复同一会话，这些边界不构成整个目标任务的累计上限。

旧版本的预算字段会在升级时移除，原「预算耗尽」记录转换为暂停，等待用户继续；升级不会擅自启动旧草稿、暂停或停止的任务。旧客户端创建请求里的预算参数不再生效，`control/budget` 返回 410，请刷新页面。

## 探索图与记忆

「探索图」记录以下节点及其关系：

| 节点 | 来源与用途 |
| --- | --- |
| 目标 | 用户提供的目标、范围、验收条件 |
| 探索步骤 | 规划器的具体方向与依赖 |
| 观察 | 阶段检查点、步骤结果和验收缺口，保留原文 |
| 执行回执 | 实际工具调用结果；失败与结果不明状态分别保留 |
| Pi 摘要 | 原生 `compaction_end` 产生的会话摘要，关联原生会话条目 |
| 历史归档 | 冷历史的引用索引，可展开原步骤和相关证据 |
| 人工线索 | 已保存的用户补充，作为用户输入单独标识 |

步骤通过 `depends_on` 建立执行依赖，通过 `source_ids` 引用启发本次探索的观察、回执或摘要。源节点必须属于同一测评。状态变化和观察节点在同一 SQLite 事务提交；原始调用回执和对应节点也在同一事务提交。

借鉴 ARTEX 的冷热分层：活跃方向及其依赖、证据祖先保持可见。已经完成或撤下、连续多轮不参与活跃链路的历史步骤，按引用折叠为归档节点。新方向再次依赖旧步骤或旧证据时，相关链路会重新显示。折叠不删除原步骤、原始观察或工具结果，不改变完成条件。

会话摘要由 **Pi 原生压缩**生成并沉淀为图中的记忆节点。业务图的冷分支归档保存成员索引及已有结果摘录，不另起一套模型压缩循环。摘要是模型派生的续接材料，证据仍应回查执行回执。

界面支持平移、缩放、适应画布、节点选择、原文分页及归档展开。大图分页面显示，分页大小仅影响本次展示，不限制总节点数；步骤清单也可分页查看。

Agent 可调用：

- `assessment_graph`：查看当前图，传 `scope` 为归档或步骤节点 ID 时展开关联内容。
- `assessment_node`：按 ID 和字符偏移读取完整节点原文与来源。
- `assessment_memory`：检索步骤、图记忆和原始执行过程，包含被折叠的历史。
- `assessment_trace`：分页读取完整执行过程。
- `assessment_checkpoint`：保存当前观察，同时保留 Pi 原生自定义条目。
- `assessment_result`：提交 completed、blocked 或 continue；完成需引用本任务真实成功调用的回执。

## 漏洞管理关联

执行过程中通过 `record_vulnerability` 成功登记的漏洞，按实际执行会话自动关联测评 ID、测评名称、步骤 ID 和步骤标题。只写在检查点或摘要中的观察不会自动生成漏洞。工具和权限沿用当前角色配置。

- **测评 → 漏洞**：在详情抽屉的「关联漏洞」中查看本次测评已登记的漏洞，打开漏洞管理详情，或在测评中查看其复现步骤、证据和来源步骤回执。
- **漏洞 → 测评**：漏洞详情显示来源测评和步骤，提供「返回测评步骤」「查看步骤与复现证据」入口。链接会定位具体步骤，不受步骤清单当前分页影响。
- **按任务分组**：漏洞管理的任务视图以测评名称展示，内部以测评 ID 分组；同名测评及相同 ID 的批量任务不会混组。任务名称搜索同时支持测评名称，原 `task_id` 参数仍保留批量任务语义；测评可用 `assessment_id` 筛选。

升级会按已有的可信执行会话补建历史关联，不按标题或标签猜测。关联快照随漏洞保存；删除测评或执行会话后，漏洞及其复现内容仍保留，已删除的测评不提供返回入口。

读取测评和读取漏洞分别检查权限。仅分享测评不会自动分享所有漏洞；仅分享漏洞也不会授予来源测评的访问或执行权限。

## Pi 与宿主的分工

Pi `SessionManager` 管理会话上下文、原生压缩、工具搜索、Skills、重试和生命周期。固定目标与步骤职责随每段执行保留，最新图态势作为有界自定义消息提供，更多历史通过图工具按需读取。结构化工具桥保留参数/输出 schema、结构化结果、annotations、namespace 和暴露策略，权限与实际执行仍由 Go 宿主处理。

规划、执行、独立验收使用 Pi 会话。规划控制会话分段后可继续，不因一次未完成规划就触发累计轮次终止。独立验收结合实际回执判断目标是否完成；模型验收不能替代人工复测。

运行中补充方向先入库，再通过 Pi 原生 `steer()` 投递给活跃执行步骤，恢复后也可回查。协作者需以自己的执行身份继续任务。

## 恢复语义

1. 工具派发前提交调用意图，结果落库后才交还 Pi。
2. 已确认回执关联原生助手条目与 tool-call ID。若回执已提交而 Pi 记录未写入就退出，恢复时补回已确认结果。
3. 结果未确认的调用进入待核对，不自动重放。暂停与停止等待本地执行资源收尾。
4. 已完成步骤保留，结果明确的中断步骤恢复原 Pi 会话。原会话文件缺失时明确受阻，避免静默从空会话重做。
5. 手动暂停保持暂停；选择自动恢复的任务在服务重启后恢复调度。图节点、原生摘要和归档成员均持久保存。

当前调度面向单服务进程。允许范围文字会传给规划与执行，实际工具权限继承角色、平台权限、HITL 和调用拦截；范围文字本身不是网络隔离沙箱。

新数据包括 `deep_assessments`、`deep_assessment_events`、`deep_assessment_calls`、`deep_assessment_nodes`、`deep_assessment_edges`、`deep_assessment_sessions` 和 `vulnerability_assessment_sources`。已有深度测评记录会补建图与会话索引，不恢复已撤回旧模块的 `assessments`/`long_tasks` 历史任务。删除测评会清理其任务、图和调度记录；漏洞来源快照随漏洞保留，执行会话仍按原有会话保留策略处理。

## API 与权限

所有接口需登录，使用 `assessments:read/write/delete` 和 `deep_assessment` 资源范围；执行另校验 `agent:execute` 及会话权限。

| 接口 | 用途 |
| --- | --- |
| `GET /api/deep-assessments/options` | 可用项目、角色与模型渠道 |
| `GET / POST /api/deep-assessments` | 查询列表 / 创建草稿 |
| `GET / DELETE /api/deep-assessments/:id` | 详情 / 删除非活动测评 |
| `GET /api/deep-assessments/:id?step_limit=50&step_offset=0` | 最近步骤的分页详情 |
| `POST /api/deep-assessments/:id/control/:action` | start、pause、cancel、guidance、answer、retry |
| `GET /api/deep-assessments/:id/graph?scope=&limit=80&offset=0` | 折叠图或展开指定节点 |
| `GET /api/deep-assessments/:id/graph/node?node_id=…&offset=0` | 节点原文 |
| `GET /api/deep-assessments/:id/vulnerabilities?limit=20&offset=0` | 当前账号可读的关联漏洞 |
| `GET /api/deep-assessments/:id/vulnerabilities/:vulnerabilityId` | 属于该测评的漏洞详情和来源步骤 |
| `GET /api/deep-assessments/:id/steps/:stepId` | 单个步骤，用于跨分页定位 |
| `GET /api/deep-assessments/:id/events?after=0` | 增量事件 |
| `GET /api/deep-assessments/:id/receipts?offset=0` | 工具回执 |
| `GET /api/deep-assessments/:id/report` | 包含当前状态及缺口的阶段报告 |

控制请求携带 `revision`；结果不明的步骤重试另需 `reconciled:true`，资源清理未确认另需 `cleanup_confirmed:true`。

## 验证边界

隔离回归验证旧预算不生效、超过原步骤/分段上限仍能继续、冷分支折叠与活跃链路恢复、原始 Pi 摘要回查、图来源隔离、重启恢复和真实 Pi SDK 模拟模型闭环。浏览器回归检查无预算表单、图渲染、节点读取、抽屉交互、桌面与手机布局，原批量任务回归仍保留。

这些测试验证执行机制，不等于已完成真实目标的多天效果、发现质量或成本对照试验。
