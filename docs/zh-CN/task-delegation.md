# 任务委派与主动请示

在「深度测评」工作台点击 **交代任务**，用自然语言描述结果，选择项目（可选）、允许使用的工具和预算，点击「交给智能体」。不需要先填写完整目标、范围和验收表单。原来的结构化「新建测评」入口继续可用。

## 工作闭环

1. **理解任务**：Pi 以无执行工具的请求提取意图、目标、范围、交付物和验收标准。原始描述、明确提供的条件、模型假设分别保存。已选择项目的资料可用于理解；模型不能自行绑定另一个项目。
2. **必要澄清**：缺少执行所需信息时，展示问题、原因、选项与建议。单纯知识问答或状态询问生成答复，状态为 `answered`，不建立执行步骤；它不会假装读取未提供的其他任务状态。
3. **自主执行**：信息完整后进入已有持久任务引擎，规划步骤并调用所选工具。权限、预算与工具审批沿用已有设置。
4. **阶段汇报**：规划更新、步骤完成、提出问题、答复及任务结束时，从数据库生成已完成、未完成、阻碍、下一步和执行 ID。报告在页面自动刷新，事件与 Markdown 导出保留历史；任务详情保留最近 50 份快照，不编造百分比。
5. **主动请示**：规划器或执行者可调用原生 `ask_owner`。步骤问题只等待该分支，既有独立步骤继续；全局规划问题暂停新步骤。没有可继续的工作时释放模型运行与执行资源，`awaiting_input` 等待时间不扣运行时长，也不轮询模型消耗 Token。
6. **答复续跑**：点击「答复并继续」。系统校验问题 ID、版本和当前操作者权限，将答复接回原步骤的工具往返记录，保留已完成结果。相同答复重复提交不会再执行，矛盾或过期答复返回 409。

普通请示只包含澄清和业务选择，不替代 HITL。答复不扩大工具集合、项目、范围或预算；需改变这些条件时，应调整任务设置或建立新任务。用户补充方向会增加任务版本，使旧的未答问题失效。

## 持久化与恢复

草稿、任务约定、问题、答复、报告与执行状态共用现有 assessment JSON 存储，不另建第二套编排引擎，也不创建隐藏聊天。问题状态与相关步骤转换在同一数据库事务中提交；报告事件与状态同步提交。

服务重启后，未回答的问题仍在。已经提交、尚未开始续跑的答复会保留恢复请求，启动及运行槽位释放时再次尝试。权限撤销、预算不足等情况会保存答复并返回 `resume_error`，需要处理该原因后恢复。外部工具的中断结果仍标为不确定，不能由问答机制自动重放。

## API

创建并开始理解任务（仍需选择可用工具）：

```http
POST /api/assessments
Content-Type: application/json

{
  "request": "帮我整理所选项目的已有材料，报告已验证事项和证据缺口，不访问新的目标。",
  "project_id": "已有项目 ID，可省略",
  "tools": ["已注册工具名称"],
  "auto_start": true
}
```

`assessment:write` 控制创建；`auto_start` 另需 `agent:execute`。创建成功但暂时不能开始时返回 201 和 `start_error`，任务已保存，不应重复创建。

答复并继续：

```http
POST /api/assessments/{id}/questions/{questionId}/answer
Content-Type: application/json

{"revision": 2, "answer": "按模块组织报告，保留所有证据缺口。"}
```

需要任务写权限及 `agent:execute`，按答复者当前权限恢复。问题、最新报告在 `GET /api/assessments/{id}` 中；报告事件通过原 events 游标接口读取。列表不返回完整草稿、问题答复或报告内容。

## 验证与边界

自动化测试覆盖：模糊任务不提前执行、缺失字段兜底、明确范围与验收条件不被模型扩写、纯问答不执行、独立分支继续、规划与问题并发、重复与过期答复、重启与队列恢复、权限检查及 UI 转义。浏览器已检查接单表单、建议选项、答复和报告展示。

隔离的真实模型验收使用合成材料及唯一回声工具：先提出澄清，答复后调用工具一次，输出证据与阶段报告，最终完成；未访问测试目标或修改生产服务。此验证不代表复杂任务、所有模型或长时间运行均已验收，也不代表已测量通用意图识别准确率。

当前入口是工作台与 API；聊天/机器人自然语言自动分流、跨项目名称消歧、站外通知、ARTEX 统一适配器仍属于后续工作。
